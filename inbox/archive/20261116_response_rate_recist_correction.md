这条意见说得对，我之前那句"肿瘤缩小 30% 以上就算应答"讲得太简化了。按 RECIST 1.1，判定 PR 光看靶病灶缩小还不够。

## PR 要同时满足三个条件

| 条件 | 要求 |
|---|---|
| ① 靶病灶 | 直径总和比**基线**缩小 **≥ 30%** |
| ② 非靶病灶 | 不能进展（评估为 Non-CR/Non-PD 或未评估） |
| ③ 新病灶 | **不能出现**新病灶 |

只要非靶病灶明确进展，或者出现了新病灶，即使靶病灶缩小了 50%，这次评估的总体结果也是 **PD（疾病进展）**。

CR 的要求更严格：所有靶病灶和非靶病灶全部消失，病理淋巴结短径 < 10 mm，并且没有新病灶。

## 确认（confirmation）

单次评估达到 CR 或 PR 还不算最终的应答，还要看后续评估能不能**确认**：

- 通常要求**间隔 ≥ 4 周**的下一次评估仍然是 CR 或 PR，这次应答才算"确认的应答"。
- RECIST 1.1 规定：**单臂试验**中，如果应答是主要终点，必须确认；**随机对照试验**中，RECIST 本身不强制要求确认，但很多方案仍会要求。

具体按哪种规则来，以项目的方案和 SAP 为准。

## 对应到 ADaM 和编程

在 ADRS 里，这几层逻辑一般会分成不同的参数：

| PARAMCD（示例） | 含义 |
|---|---|
| `OVRLRESP` | 每次访视的总体评估（综合靶病灶、非靶病灶和新病灶） |
| `BOR` | 最佳总体应答（未确认） |
| `CBOR` | 确认的最佳总体应答 |

ORR 通常基于 **确认的 BOR**，算法是 CR 或 PR 的人数除以分析人群的人数。所以前面代码里的写法要做个修正：

```r
adrs |>
  filter(PARAMCD == "CBOR") |>              # 用确认的 BOR，而不是单次评估
  ...
  summarise(n_resp = sum(AVALC %in% c("CR", "PR")))
```

PARAMCD 的具体名称各家公司不一样（比如 `BESTRSP`、`CBESTRSP`），要以项目的 ADaM 规格书或 define.xml 为准。

其他疾病领域的应答标准也是这样，前面表格里的 ACR20、PASI 75 都是简化说法，完整定义要看各自的评估标准和 SAP。
